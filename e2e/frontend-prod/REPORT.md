## 🔴 결함 — Admin 계정이 USER 전용 라우트에 진입하면 빈 화면(blank page)

**재현**: Admin으로 로그인한 상태에서 `/promotions/:id` 또는 `/me/participations`처럼 `role="USER"`가 필요한 라우트로 이동(직접 URL 입력/새로고침 포함)

**증상**: URL은 `/`로 바뀌지만 `#root`가 완전히 빈 채로 아무것도 렌더링되지 않음(콘솔 에러도 없음). 새로고침해도 동일.

**원인** (`frontend/src/router.tsx` `ProtectedRoute`, 26번째 줄):
```tsx
if (role && user.role !== role) return <Navigate to="/" replace />;
```
role 불일치 시 리다이렉트 대상이 항상 `/`로 고정되어 있습니다. 그런데 `/` 라우트 자체도 `role="USER"`를 요구하므로(`router.tsx` 36번째 줄), ADMIN이 `/`로 리다이렉트되면 그 자리에서 다시 같은 조건에 걸려 또 `/`로 리다이렉트를 시도합니다. React Router가 이 무한 리다이렉트를 감지해 렌더링을 중단시키는 것으로 보이며, 결과적으로 사용자에게는 흰 화면만 보이고 아무 안내도 없습니다.
- USER가 ADMIN 전용 라우트(`/admin/promotions` 등)에 잘못 들어간 경우는 `/`가 USER에게는 정상 접근 가능한 경로라 문제없이 리다이렉트됩니다 — 그래서 기존 테스트에서는 발견되지 않았던 것으로 보입니다.

**영향도**: 중간. 실사용 시나리오상 Admin이 `/promotions/:id`나 `/me/participations` URL을 직접 칠 일은 드물지만, 즐겨찾기/공유된 링크를 관리자가 실수로 열거나, 로그인 세션이 꼬여 있는 상태에서 이전에 열어둔 탭을 새로고침하는 경우 등에는 아무 설명 없는 흰 화면을 마주치게 됩니다.

**수정 제안**: `ProtectedRoute`의 리다이렉트 대상을 사용자의 실제 역할에 맞게 분기(`user.role === 'ADMIN' ? '/admin/promotions' : '/'`)하면 해결됩니다.

**스크린샷**: `23-BUG-admin-blank-page-on-user-route.png`

## 참고 사항

- Admin 계정으로 조회한 프로모션 목록에는 이전 백엔드 API 레벨 E2E 테스트(`e2e/backend-prod/`)에서 정리하지 못하고 남겨둔 `prod e2e ROULETTE`(상태: 종료)가 그대로 보입니다 — 실사용자에게는 노출되지 않으며(ONGOING/UPCOMING만 목록에 표시), 재추첨 불가 규칙(DB 트리거)으로 인해 삭제할 수 없었던 데이터입니다.
- 이번 테스트로 만든 User(`fe2euser01`)와 프로모션("프론트 E2E 테스트 프로모션(수정됨)", 조기종료 처리됨)은 실사용자 데이터와 섞이지 않도록 종료 처리는 했으나, DB 레코드 자체는 위와 동일한 이유(ROULETTE 참여가 없는 DIRECT 프로모션이라 실제로는 삭제 가능함에도) 정리 여부를 사용자 확인 후 진행하는 것이 안전하다고 판단해 별도 조치 없이 남겨두었습니다. 정리를 원하시면 말씀해 주세요.
